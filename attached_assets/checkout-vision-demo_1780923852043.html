Why edge inference

The model runs in-browser via TensorFlow.js. Streaming raw video from hundreds of in-store cameras to the cloud is bandwidth-prohibitive — the same constraint I managed across millions of connected vehicles. The PM decision is what to compute locally vs. send up.

Detection trust = adoption

The confidence threshold is the operating point on the precision/recall curve. Too low floods the cart with false adds; too high misses real items. Where you set it is a business decision about customer trust, not just a technical one.

What production adds

A real system swaps COCO's 80 generic classes for a retail-specific model, fuses multiple camera angles to handle occlusion, and escalates low-confidence events to a cloud reasoning layer (a VLM) for the hard edge cases.

How this prototype works

When you start the camera, each video frame is passed to COCO-SSD — a convolutional neural network with a MobileNet v2 backbone — running locally through TensorFlow.js. The model returns a list of detected objects, each with a class label, a bounding box, and a confidence score. The app draws those boxes, then applies a small amount of product logic on top.

Camera frame→ CNN detects objects→ Confidence filter→ Debounce + presence logic→ Virtual cart

Two pieces of logic make it behave like a real store rather than a flickery demo. A debounce requires an item to appear for several consecutive frames before it's added — this suppresses momentary false detections. A presence timeout removes an item only after it has been gone from view for over a second — so brief occlusion (a hand passing over a product) doesn't drop it from the cart. Both are deliberate trust safeguards, not happy-path shortcuts.

The key control

The confidence slider sets the model's operating point. Lowering it catches more items but admits false adds; raising it is safer but misses real items. In a real checkout-free store, where you set that threshold is a business decision about customer trust and shrink — the same precision/recall tradeoff you'd read off an ROC curve.

A short history of how machines learned to see

Computer vision didn't start with deep learning. It's the product of six decades of work, and the breakthrough ideas trace back further than most people expect — to a pair of neuroscientists studying cats.

1959–1962 · THE BIOLOGY
Hubel & Wiesel discover orientation-selective neurons
Recording from a cat's visual cortex, they found individual neurons that fire only for a line at a specific angle, or motion in a specific direction. Vision is built hierarchically: simple features first, combined into complex ones layer by layer. They won the 1981 Nobel Prize — and unknowingly wrote the blueprint for the CNN.
1980 · THE ARCHITECTURE
Fukushima's Neocognitron
A neural network directly inspired by Hubel & Wiesel, stacking layers of simple and complex feature detectors. The conceptual ancestor of every CNN that followed.
1989–1998 · THE METHOD
LeCun's LeNet learns the filters
Yann LeCun combined convolution with backpropagation so the network could learn its feature detectors from data instead of having them hand-designed. LeNet read handwritten digits on real bank checks — the first CNN doing useful work at scale.
2012 · THE EXPLOSION
AlexNet wins ImageNet
A deep CNN crushed the ImageNet competition, cutting error rates dramatically and beating every hand-engineered approach. Trained on GPUs, it kicked off the modern deep-learning era of computer vision.
2015–2016 · REAL-TIME DETECTION
SSD & YOLO make detection fast
Earlier detectors were accurate but slow. Single-shot detectors like SSD (the "SSD" in COCO-SSD) and YOLO detect and localize many objects in one pass — fast enough for live video. This prototype uses exactly that lineage.
2020–2026 · ATTENTION & REASONING
Vision Transformers and Vision-Language Models
Transformers replaced convolution's local sliding window with self-attention, letting a model relate every part of an image to every other part at once. Vision-Language Models go further — reasoning about images in natural language ("is this shelf compliant with the planogram?"), not just classifying them.

How a CNN actually sees

A CNN's core operation is the convolution: a small grid of numbers (a filter) slides across the image, and at each position multiplies itself against the pixels underneath and sums the result into a single number. One filter might be tuned to detect vertical edges, another horizontal ones — exactly like a Hubel-Wiesel neuron. The output is a "feature map" showing where that pattern appears.

Stack these and the features grow in sophistication:

  • Early layers detect edges, colors, and angles.
  • Middle layers combine those into corners, textures, and simple shapes.
  • Deep layers assemble shapes into parts, then whole objects — "this is a bottle."

Between layers, pooling downsamples — keeping the strongest signal in each region so the network becomes robust to small shifts in position. Because the same small filter is reused across the whole image (weight sharing), CNNs are remarkably efficient — which is what lets one run live, in your browser, on a webcam feed.

CNNs vs. human vision

CNNs were inspired by biology but differ from it in important ways. Human vision is predictive — your brain constantly guesses what it expects to see and checks incoming light against that guess (which is why optical illusions fool us). It's selective — a tiny high-resolution fovea darts around a scene 3–4 times a second rather than processing everything at once. And it carries a world model — you know an object still exists when it's hidden behind another. A CNN, by contrast, is purely feedforward: it processes every pixel equally, has no memory between frames unless you add it, and doesn't predict — it classifies. The frontier in 2026 is closing that gap by pairing fast CNN detection with transformer-based reasoning that begins to approach human-like context and understanding.

Why this matters for unattended retail

The winning architecture is a hybrid: lightweight CNNs at the edge (on the camera) for fast, cheap, reliable detection — and a cloud reasoning layer that only sees the hard cases. That mirrors the edge-vs-cloud signal prioritization problem I managed across millions of connected vehicles: you can't move all the raw data, so you decide intelligently what to compute locally and what's worth escalating.
